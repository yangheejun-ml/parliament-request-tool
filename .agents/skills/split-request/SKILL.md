# 자료요구서 문항 목록 만들기

## 목표

작업 폴더 맨 위에 `split.py` 하나를 만들거나 수정한다. 이 코드를 실행하면 `원문/*.pdf`에서 `data/문항목록.csv`를 UTF-8-SIG로 만들며, 사용자가 교체해 둔 문항목록 기준본과 모든 행·열 값이 일치해야 한다.

## 작업 전 확인

1. `AGENTS.md`를 따르고 `PROGRESS.md`, `CONTEXT.md`, `problem.md`, `design.md`를 정해진 순서로 읽는다.
2. `처리지침.md` 제2장, `data/문항목록.csv`, 기존 `split.py`, `원문/*.pdf`를 확인한다.
3. `pypdf` 설치 여부를 먼저 확인한다. 없으면 `pip install pypdf`를 사용자에게 보여 주고 허락을 받은 뒤 설치한다.
4. 기준본인 `data/문항목록.csv`는 비교가 끝날 때까지 덮어쓰지 않는다. `99_완성본_잠금`은 열지 않는다.

## 분해·저장 규칙

- Python 표준 라이브러리와 `pypdf`만 사용한다. 새로 만드는 코드 파일은 작업 폴더 맨 위의 `split.py` 하나뿐이다.
- CSV 열 순서는 `파일명 | 위원회 | 의원 | 제출기한 | 문항번호 | 요구내용 | 세부항목 | 비고`로 고정한다.
- 첫 줄 `○○위원회 ○○ 의원실 자료요구서`에서 위원회와 의원을 뽑는다.
- `수신: … 제출기한: YYYY. M. D.(요일) HH:MM까지` 줄에서 제출기한을 찾아 `YYYY-MM-DD`로 저장한다.
- `수신:`, `담당 보좌관:`, `끝.` 줄과 이름·연락처는 문항에 넣거나 별도로 저장하지 않는다.
- 줄 맨 앞의 `숫자.`는 새 문항이다.
- `가.`, `나.` 등은 같은 문항의 세부항목이다. 여러 세부항목은 한 셀에서 ` / `로 잇고 줄바꿈 문자를 넣지 않는다.
- `※` 줄은 같은 문항의 비고다. 저장할 때 맨 앞의 `※`와 뒤따르는 공백을 제거한다. 여러 비고는 ` / `로 잇는다.
- 그 밖의 줄은 바로 앞 항목에 공백 하나로 이어 붙인다.
- 특정 파일명·문항번호·요구내용을 정답으로 코드에 직접 쓰지 않는다. 규칙으로 처리한다.

## 기준본에 맞게 split.py 만들기

1. 교체된 `data/문항목록.csv`를 UTF-8-SIG로 읽어 메모리에 보관한다.
2. 기존 `split.py`가 있으면 재사용하되, 기준본과 다른 형식이나 파싱 규칙만 작은 단위로 고친다. 없으면 위 규칙을 구현한 `split.py`를 만든다.
3. 작성한 파싱 함수를 불러 원문 PDF의 결과를 메모리에서 계산한다. 이 단계에서는 CSV를 쓰지 않는다.
4. `(파일명, 문항번호)`를 키로 행 수, 열 이름과 순서, 모든 셀을 기준본과 비교한다.
5. 불일치가 있으면 열별 불일치 건수와 대표 차이를 확인해 일반 규칙을 고친다. 현재 기준본에서는 세부항목을 ` / `로 잇고 비고의 선행 `※`를 제거해야 한다.
6. 기준본과 완전히 일치한 뒤에만 `split.py`를 실행해 `data/문항목록.csv`를 만든다. 생성본을 다시 읽어 기준본과 전수 비교한다.

## 확인

- 파일별로 다음 표를 제시한다.

  `파일명 | 파일명의 문항 수 | 뽑은 문항 수 | 마지막 번호 | 번호 연속 | 일치(O/X)`

- 파일명의 `_숫자문항.pdf` 값, 추출 행 수와 마지막 번호가 같아야 하고 문항번호는 1부터 연속이어야 한다.
- 전체 78개 문항, 8개 열과 모든 셀 값이 기준본과 일치해야 한다.
- 세부항목에는 줄바꿈이 없어야 하고 ` / ` 구분자를 사용해야 한다. 비고에는 선행 `※`가 없어야 한다.
- `수신:`, `담당 보좌관:`, `끝.`과 전화번호 의심값이 저장된 건수는 0이어야 한다.
- 세부항목·비고가 있는 문항 3개를 골라 `원문 PDF 추출값 | CSV 저장값 | 일치` 형태로 나란히 제시한다.
- 일치가 하나라도 X면 원인을 찾아 `split.py`를 고치고 다시 실행한다. 모두 O일 때만 완료로 보고한다.
- 원문 PDF와 기존 다른 `data` 파일이 수정되지 않았는지 확인하고, `PROGRESS.md`에 완료·검증 결과와 남은 일·막힌 점을 기록한다.
