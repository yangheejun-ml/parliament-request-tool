# 배분 규칙 보강

## 언제 쓰는지

- `web/engine.js`의 1순위 오답을 분석해 배분기준표를 보강할 때 사용한다.
- 키워드가 여러 과에 걸리거나 일반 키워드가 세부 키워드보다 앞서는 원인을 찾아야 할 때 사용한다.
- 변경 전후의 시험 40건과 접수대장 520건 정확도, 신규 오답 여부를 함께 검증해야 할 때 사용한다.

## 순서

1. `AGENTS.md`, `PROGRESS.md`, `CONTEXT.md`, `problem.md`, `design.md`, `처리지침.md` 제3장을 읽고 조직도·원본 배분기준표·시험 문항·접수대장·엔진을 확인한다.
2. 원본 규칙으로 시험 40건과 접수대장 520건을 실행한다. 1순위 오답을 충돌 키워드, 미매칭, 동순위 등 원인별로 묶고 원인마다 제외어 추가·키워드 추가·우선순위 조정 중 한 가지 방법을 제안한다.
3. 사용자의 선택을 받은 뒤 원본 배분기준표를 건드리지 않고 사본을 만든다. 선택한 규칙만 사본에 반영하며, 과 이름은 조직도 26개 과 안에서만 사용한다.
4. 원본과 사본을 각각 같은 엔진으로 시험 40건과 접수대장 520건에 실행한다. 1순위·3순위 안 정확도, 새로 맞은 문항, 새로 틀린 문항, 조직도 밖 후보와 실제 변경 행을 비교한다.
5. 변경 규칙과 전후 결과를 표로 보고하고 `PROGRESS.md`에 완료·검증 결과·남은 일·막힌 점을 기록한다.

## 끝나는 조건

- 원본 배분기준표는 수정되지 않았고 사본의 행 수·열 순서·나머지 규칙이 유지되어야 한다.
- 사용자가 승인한 규칙만 바뀌고, 실제 변경 행과 열이 승인 내용과 정확히 같아야 한다.
- 시험 40건의 1순위 정답이 30건 이상이고 시험·접수대장에서 새로 틀린 문항이 0건이어야 한다.
- 3순위 안 정확도, 조직도 밖 후보 0건과 변경 전후 결과를 함께 확인해야 한다.
- 조건을 충족하지 못하면 성공으로 표시하지 않고 원인을 `확인필요`로 보고한다.

## 하지 말 것

- 원본 배분기준표, 조직도, 시험 문항과 접수대장을 덮어쓰거나 삭제하지 않는다.
- 사용자가 고르지 않은 규칙을 사본에 추가·수정하지 않는다.
- 규칙·부서명·시험 정답을 엔진 코드에 직접 쓰지 않는다.
- 조직도 밖 부서를 만들거나 AI 추천을 최종 배분으로 자동 확정하지 않는다.
- 시험 점수만 올리려고 특정 시험번호나 요구내용 전체를 예외 규칙으로 넣지 않는다.
